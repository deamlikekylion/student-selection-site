01 / 产品定位

把课程选题，组织成一条清晰的流程。

学生选题系统面向课程设计、课程项目等按班级开展的选题活动，把身份核验、题目准备、报名、抽签、限时确认和结果归档连接起来。

01 · 参与体验

学生知道下一步做什么

从“是否报名成功”到“前面还有几人”，再到“轮到本人”和“结果已保存”，关键阶段有明确提示。学生可以持续查看个人报名与历史选题记录。

02 · 活动组织

教师按规则组织活动

先准备题目与容量，再一次性公布时间规则。报名截止后自动冻结有效名单并抽签，到计划时刻进入选题队列；暂停、补选、调整均有规则。

03 · 人员治理

管理员维护可信基础

通过名册、审核和账号状态控制参与资格；批量导入先预览再确认，遇到冲突保留现有账号，并通过审计记录查看关键操作。

产品主线规则提前公布 → 过程持续可见 → 结果持久保存

报名先到先得只决定能否进入活动，具体题目的选择顺序由冻结后的抽签决定。

适用场景能够提供的帮助使用条件
课程设计集中选题一个活动内维护多道题目，按容量报名并依序选题。提前核对班级、题目总容量与时间安排。
教师多轮开展课程项目个人题库可重复使用，每次活动采用独立的题目副本与结果记录。按每轮活动独立发布，避免直接改动历史结果。
本地运行与受控试用Windows可执行程序启动后，在浏览器完成三角色流程。明确数据目录、服务地址及浏览器会话。

03 / 三角色协作

同一场活动，三种明确的工作视角。

业务角色与权限由后端校验。学生关注参与和结果，教师负责本人活动，管理员负责身份基础与账号管理。

角色主要工作区核心能力权限边界
学生活动大厅 / 我的报名 / 我的选题结果名册匹配注册、登录改密、浏览题目、报名取消、版本重确认、轮次选题、结果查询。只参与同班可见活动；只有当前轮到本人时可以确认选题。
教师个人题库 / 活动与题目 / 报名与抽签 / 选题结果创建草稿、导入题目、发布规则、管理队列、暂停恢复、统计导出、结束后带原因调整。只管理本人题库和本人负责活动；不能绕过容量或随意改动冻结题目。
管理员师生资料 / 名册与资格核验 / 账号与审计CSV导入、名册维护、审核和停用、账号搜索、解锁、签发设置码或重置码、查看审计。管理操作仍受账号角色和状态校验；代码发放需先完成线下身份核验。
协作示例：管理员先核实名册；教师准备题目并发布活动；学生报名、按抽签顺序选题；教师导出同版本结果，管理员保留审核和操作记录。
04 / 完整业务流程

从名册到结果，八步形成闭环。

准备、发布和报名分开处理，避免教师还在编辑草稿时，报名时间已经悄悄消耗。

  1. 01

    准备身份

    管理员建立名册或导入师生账号，学生按要求完成注册、审核或首次改密。

  2. 02

    建立草稿

    教师配置班级、报名时长和每人时限，手工添加、题库复制或批量导入题目。

  3. 03

    发布规则

    确认题目总容量，公布报名截止后的等待时长；发布时才开始报名计时。

  4. 04

    报名确认

    学生在截止前报名或取消；题目发布后发生变更时，已报名者重新确认当前版本。

  5. 05

    冻结与抽签

    截止后系统筛选有效报名、保存身份快照并生成固定顺序；无人有效报名则结束。

  6. 06

    按时启动

    到计划时间自动开始正常轮次，学生按顺序在限定时间内选择。

  7. 07

    一次补选

    正常轮超时者按原顺序排到正常队列后补选，再次超时记为未选题。

  8. 08

    归档与导出

    学生查看个人结果；教师查看统计、导出CSV与快照说明，必要时带原因调整。

发布是时间规则的起点。选题计划开始时间 = 发布成功时刻 + 报名时长 + 截止后的等待时长。个人实际轮到的时刻还会受前方同学提前完成、超时和教师暂停影响。
05 / 六步上手指南

从资料准备到结果归档，六步完成选题。

管理员准备师生资料，教师配置并发布活动，学生按顺序完成选题。各角色在同一流程中协作，结果统一保存。

顺序使用步骤关键规则处理结果
01 · 管理员预览并导入师生资料。正常数据、相同记录跳过、账号信息冲突和错误行反馈。合法记录按规则保存，已有账号不会被导入自动覆盖。
02 · 教师准备题目并发布活动。题目容量汇总，以及报名时长、截止后等待时长、每轮时限三种独立参数。草稿准备完成后发布，页面显示明确的报名截止与计划开始时刻。
03 · 学生报名、取消，再次报名。活动名额限制、重复报名、取消后释放名额。报名数与剩余名额一致变化，报名不等于已选定具体题目。
04 · 教师 / 学生截止后分别查看抽签结果。教师完整名单、学生本人序号、前方人数和计划开始时刻。有效名单被冻结，系统生成并保存固定顺序。
05 · 学生 / 教师依次选题，教师暂停后恢复。非当前人限制、成功后推进、暂停时禁止提交、恢复沿用剩余时间。只有当前学生可确认；成功、超时和暂停均按既定状态规则处理。
06 · 学生 / 教师查看个人结果与汇总，下载结果明细。结果持久保存、统计与CSV内容一致、导出版本和调整原因。学生能回看本人结果，教师能取得可归档的汇总与明细。

使用前准备

首次试用可使用独立数据目录，先核对账号、班级和题目容量。切换角色时使用不同浏览器或独立会话，避免多个标签页共享登录身份。

时间安排

教师分别设置报名时长、报名截止后的等待时间和每人选题时限。正常轮超时的学生在正常队列结束后获得一次补选机会，补选仍使用活动配置的时限。

06 / 学生端体验

清楚地报名、等待、选择和回看。

学生操作围绕三个入口展开：活动大厅用于发现活动，我的报名用于跟踪进度，我的选题结果用于长期查询。

01 / 身份与账户

自行注册需要学号、姓名和班级与名册匹配，审核后才能登录。管理员直接创建的有效账号可按规定首次改密；首次启用和忘记密码分别提供入口。

个人可修改密码并退出登录，账号锁定由管理员解除。

02 / 浏览与报名

进入同班已发布活动，查看题目介绍、完成要求、难度、指导教师及剩余容量；通过搜索与筛选缩小范围。

报名页展示总名额、已报名人数、剩余名额、报名截止与计划选题开始时间。截止前可取消，重复报名不重复占位。

03 / 等待与轮次

“我的报名”展示本人抽签序号、前方尚未完成的人数和当前阶段。等待人数包含当前正在选题的人。

状态同步与倒计时按秒更新，慢请求未返回时不会叠加新请求；实际截止以服务端时间为准。

04 / 确认与记录

轮到本人时选择题目，在确认窗口核对题目和指导教师，阅读并勾选规则后提交。后端同时检查身份、时间、当前人和容量。

成功后显示持久化结果；历史结果页保留指导教师、确认时间、调整说明，并区分补选未选、未入名单和活动作废。

网络中断时的体验：提交响应丢失后，页面会尝试查询结果；若仍无法连接，会明确提示结果未知。恢复网络后应刷新核验，不能仅凭超时提示判断失败。
07 / 教师端能力

准备充分，再把活动稳定地推进下去。

教师工作台提供个人题库和创建活动入口；进入活动后，准备、名单与结果分别放在独立版块中。

可重复利用的个人题库

维护题目名称、内容、完成要求、难度和容量，支持搜索与分页。加入活动时生成独立副本；修改或删除题库原件不改变已有活动快照。

充分准备的草稿阶段

草稿可以修改活动名称、班级、报名时长和每人时限。题目可手工添加、从题库复制，或在草稿内批量导入；报名计时尚未开始。

一次公布的活动规则

发布确认集中展示总容量及时间安排。发布时间由服务器确定，开始报名后锁定时间规则，避免参与者按不同版本时间安排准备。

带版本控制的题目变更

发布后修改题目需要填写原因，并使已报名学生重新确认。容量不得缩减到已报名人数以下；冻结后停止修改题目。

轮次组织与异常核验

在“报名与抽签”查看学生序号、学号、姓名和状态。正常自动流程之外，可暂停活动并说明原因；核验后恢复原剩余时间。

统计、导出与结果调整

在“选题结果”查看汇总及各题占用情况。活动结束后，可带原因调整已有最终结果，调整仍受题目容量约束，并记录审计。

进行中活动不能直接作废。选题开始后应先暂停并核验；开始前可以说明原因作废，同时保留历史。
08 / 管理员能力

让参与资格和账号处理有据可查。

管理员维护系统的身份入口，重点解决“谁能进入、信息是否一致、账号发生问题如何恢复”。

管理环节处理方式对使用者的价值
名册与注册核验导入或维护学生名册；学生自行注册必须匹配授权名册，再进行资格审核。减少不属于本班或信息不一致的账号进入活动。
审核、停用与搜索通过姓名/学号、班级和状态进行查询，执行审核或停用；审核操作记录决定、原因与操作者。批量人员管理更清晰，也便于后续追查。
批量建号学生支持仅建名册或同时创建账号；教师导入直接创建账号，逐行反馈处理结果。减少逐个录入；冲突不会自动覆盖已有账号和记录。
首次启用单独创建教师账号后签发一次性设置码，教师在登录页自行设置密码。教师不必直接使用管理员指定的长期密码。
忘记密码线下核验身份后签发一次性重置码，15分钟有效；重新签发后旧码失效。恢复流程与首次启用分开，使用目的清楚。
账号锁定处理对有效账号执行解除锁定；不需要仅因锁定而重置密码。减少不必要的密码变更。
操作审计查看审核、发布、报名、题目变更、暂停、提交、调整和导出等关键动作。保留问题处理线索和时间依据。
09 / 时间与选题规则

参数可配置，边界要明确。

以下参数来自当前版本使用手册及实现。报名时长、报名截止后的等待时长和每人每轮时限是三个独立设置。

参数当前规则说明
报名时长1—43,200分钟，整数，最多30天从实际发布成功开始计时；草稿准备阶段不消耗报名时间。
截止后等待1—1,440分钟，默认10分钟为有效报名学生留出等待与准备时间。
每人每轮时限60—300秒，默认300秒正常轮与补选轮使用相同时限，发布后锁定。
单题容量1—100人，整数报名总名额为活动内全部题目容量之和。
报名窗口开始时间 ≤ 服务端当前时间 < 截止时间满额停止新报名，取消报名释放名额。
重复提交同一成功结果可重复确认不会多占题目容量；已有最终结果不能自行改选另一题。
轮次超时正常轮后补选一次按原抽签顺序排补选；再次超时记录未选题。
刷新页面沿用服务端原截止时刻刷新、切换页面或重复请求不会重新获得完整时限。
时间示例 · 仅用于解释规则

09:00发布，报名30分钟，等待10分钟，每轮120秒。

09:00开始报名
09:30截止、冻结与抽签
09:40队列计划启动
最多120秒/人提前确认则立即推进

09:40是整个队列的开始时刻，并非每位学生固定的选题时刻。教师暂停会影响后续等待时间；学生应保持活动页面开启。

展开：活动状态与异常恢复规则

活动主要状态为草稿、已发布、已冻结、已抽签、运行中、已暂停、已结束及已作废。服务端定期调度自动冻结、抽签与启动，正常运行约每0.5秒检查。

服务重启时，运行中的活动会暂停并保留最近心跳记录的剩余时间；若错过新活动计划启动时间超过5秒，恢复检查会暂停该活动，保留首位完整的教师设置时限，等待核验，避免悄悄扣除离线时间。

暂停时学生不能提交；恢复沿用剩余时间。被冻结的有效名单和身份快照用于后续结果及导出。

10 / CSV批量导入

两类导入，采用不同的错误处理策略。

人员资料按合法行保存，活动题目则整批校验。两类都先预览再确认，支持CSV UTF-8文件；当前不直接导入XLSX。

对比项管理员：师生资料教师：活动题目
使用入口管理员“导入师生资料”。草稿活动“导入活动题目”。
每批规模1—100条人员记录。1—50道题目，文件最多48KB。
主要字段学生：学号、姓名、班级；教师：账号、姓名。题目名称、题目介绍、完成要求、难度、容量。
新记录可仅建立学生名册，或创建有效账号；新账号生成随机临时密码并要求首次改密。新增到本活动；指导教师自动使用活动负责人，不写入个人题库。
重复与冲突相同账号跳过；账号角色、姓名或班级冲突时反馈字段，不覆盖现有账号。相同题目跳过；同名不同内容、本批重名或非法字段须修正。
出现错误确认后合法行保存，错误行反馈原因，避免一行错误阻塞整批合法人员。存在错误时整批不写入，修正后重新预览。
预览失效保存前重新核验已有名册，变化后要求重新预览确认。题目集合已变化或活动已发布时拒绝确认。
导入后可下载处理清单；临时密码在该批结果弹窗中领取，遗失后走重置流程。显示新增/跳过数量，活动总名额随新增题目容量更新。
当前版本已移除CSV模板下载按钮。导入弹窗保留表头、编码和规则说明；仓库“测试用例/导入样例”提供正常与异常样例。把Excel表格另存为CSV UTF-8后再导入，学号应按文本处理。

导入之前

核对授权名单、账号字段和班级，避免同批重复。预览中先读清“新增”“跳过”“冲突”的区别；存在账号冲突时使用“核验账号”入口定位，不直接覆盖。

导入之后

核对保存、跳过和错误数量，妥善交付新账号临时密码。题目导入遇到网络中断时先查看活动内容，再重新预览，避免凭感觉重复新增。

11 / 结果与可追溯性

让结果可查询，也能解释它如何产生。

系统把结果记录、身份快照、题目版本和操作审计连在一起，帮助教师完成归档和争议核查。

学生个人记录

汇总本人各活动的结果、题目、指导教师和确认时间；教师调整的说明随结果展示。无最终成功结果时，区分等待、未选、未入名单和作废等情况。

教师汇总统计

同时查看报名数、有效冻结数、成功选题、未选、等待、补选及排除情况，并查看各题容量、已占和剩余名额。过程快照与最终结果有明确区分。

同版本导出

CSV明细与快照说明在同一事务中生成，带题目版本、结果版本和导出时间；避免统计汇总与明细来自不同时间点。

历史身份与变更

名单冻结后保存身份快照，后续账号姓名或班级变更不重写历史导出。结束后调整必须填写原因、检查容量并保留审计。

CSV结果包含哪些信息？

活动编号活动名称学号姓名班级编号参与编号题目编号题目名称选题状态确认时间

导出采用带BOM的UTF-8，确认时间包含北京时间时区。危险公式、控制字符和带前导零的数字文本会进行安全处理；使用Excel打开时，学号列仍建议按文本导入。

12 / 一致性与过程透明

公平顺序有依据，保存结果有约束。

这些机制用于提高课堂版系统的可解释性和数据一致性；它们不等于第三方公平认证或任意规模的生产保障。

抽签可复算

发布时固定随机种子的承诺摘要；冻结后为有效参与者生成标签与名单摘要，用种子、名单摘要和标签的SHA-256值排序，形成固定顺序。同一活动沿用既有顺序。

学生界面不展示技术JSON；证明信息与审计仍保留在后端。

确认结果作为整体保存

写入事务内检查当前学生、活动状态、截止时间和题目容量，再保存结果、更新轮次并推进下一人。重复请求不会增加同一学生的成功结果或重复占位。

账号与访问校验

密码采用随机盐与PBKDF2-HMAC-SHA256保存，令牌摘要入库；后端校验角色、活动归属、班级和账号状态，并使用参数化SQL、CSRF和Origin检查。

运行故障可核验

刷新不延长时限，暂停不允许提交，重启后进入核验流程。SQLite保存用户、活动、队列和结果；关闭浏览器不等于关闭后端服务。

关键算法 · SHA-256哈希排序

随机种子与名单固定后，顺序可重复计算。

个人排序值 = SHA-256（随机种子 | 冻结编号列表摘要 | 参与编号）

创建活动时由安全随机源生成种子，发布时公布承诺摘要；截止后为有效参与者分配P001、P002等内部编号，再按个人排序值升序确定名次。P001、P002的编号大小不直接决定先后，已生成顺序会保存并沿用，排序步骤复杂度为 O(n log n)。

轮次使用“正常轮优先、再按抽签位置”的队列规则；正常轮超时者获得一次补选。状态机限制草稿、报名、冻结、运行、暂停和结束阶段允许的操作。

抽签机制的边界：当前列表摘要只包含参与编号，不包含姓名和学号，因此不能单独证明完整身份名单没有被替换；身份对应关系和冻结身份快照另存数据库。这是成熟算法的业务应用，不声称原创加密算法，也不能抵抗具有完全服务器权限的人任意篡改。

19 / 常见问题与边界

把容易误解的规则，提前说清楚。

当前已实现的功能与待完成的部署、验证工作分别说明，便于选择使用方式和安排后续部署。

报名成功是否意味着已经选中了某个题目？

不是。报名占用活动总名额，具体题目要在轮到本人时确认。先报名不等于先选题，选题顺序由冻结后的抽签决定。

错过正常轮次还有机会吗？

有一次补选。正常轮超时者按原顺序排到正常队列后，使用相同时限补选；再次超时记录为未选题。

教师发布后改了题目，我需要做什么？

阅读变更并重新确认当前题目版本。截止仍未确认者不会进入有效冻结名单；冻结后题目不再修改。

为什么“选题开始”到了，却还没有轮到我？

计划开始时间是队列启动时刻。你需要继续等待前方同学，提前完成、超时和暂停都会影响实际轮到时刻。

学生提交成功后能自行退选或换题吗？

不能。成功结果锁定；活动结束后由负责教师核验，并填写原因调整，仍受题目容量限制。

系统能发微信或短信提醒吗？

当前没有离线短信或微信通知。应保持页面开启，也可按公布的开始时间自行设置闹钟或日历提醒。

能把这个程序直接作为公网学校平台吗？

目前定位于本地运行和受控试用。正式HTTPS部署、公开发布、真实用户验收以及数小时长期稳定性仍需落实；本机测试不等同于生产容量保证。

这份介绍可以单独发给别人吗？

可以。HTML内嵌样式、交互脚本和归档示例图片，无外部字体或框架依赖；直接用浏览器打开即可，支持目录跳转、关键词定位、图片放大与打印。实际运行系统需要另行启动程序。

后续可继续推进的工作

真实参与者的实际试用与复评、更多校园网络和终端环境验证、数小时稳定性、正式HTTPS与公开部署。历史压力测试和情境反馈都不能自动代替这些工作。
